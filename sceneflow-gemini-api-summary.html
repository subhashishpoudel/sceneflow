SceneFlow — Gemini API Summary

How SceneFlow uses the Gemini API · models · prompts · voice controls · known behaviours

API Endpoint

All calls go to one endpoint

https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent

Authentication via x-goog-api-key header — key read from environment variables only, never hardcoded.

Models Used

PurposeModelResponse Type
TTS Text-to-Speech (voiceover) gemini-2.5-flash-preview-tts AUDIO — raw PCM (24 kHz, mono, 16-bit)

Image Scene image generation gemini-2.5-flash-image IMAGE — inline PNG/JPEG bytes

Prompts & Instructions Sent to the API

TTS Voiceover Generation

No fixed system instruction. The prompt is built as:

If style provided: {style instruction}

{scene narration text}

If no style: just the raw scene text.
Example style: "Speak slowly and calmly, with a cinematic tone."
Transcribe Word Timestamp Extraction

Fixed instruction sent alongside the audio:

"Transcribe the provided audio EXACTLY as spoken. Return a strict JSON array of objects, each with keys "start" (seconds, float), "end" (seconds, float), and "word" (string, lowercase). Do not include commentary, markdown code fences, or any text outside the JSON array. Preserve every spoken word in order."
Temperature set to 0.0 for deterministic output.
Image Image Generation

No fixed instruction. The raw scene description/prompt is sent directly with responseModalities: ["IMAGE"].

Why Some Voices Sound Inconsistent

No hard speed/pitch/rate controls are sent to the API. The Gemini TTS API does not expose speakingRate, pitch, or SSML — those belong to Google Cloud TTS (a different product entirely).
  • Each voice preset has its own built-in character — some are naturally faster, quieter, or more energetic than others.
  • Each TTS batch call is independent — the model can choose slightly different energy/pacing each time even with the same voice.
  • The only lever available is the Style field. A detailed instruction like "Speak at a slow, steady, consistent pace throughout. Do not whisper, rush, or change your tone." helps but is not guaranteed.

How TTS Batching Works

Scenes are batched to reduce API calls

Multiple scene scripts are joined with a \n\n paragraph break and sent as one TTS request. The combined audio is then split back into per-scene WAV files using forced alignment (local MMS_FA model) + FFmpeg.

Max 15 scenes per chunk · Max 6,000 characters per chunk · Timeout: 360 seconds per request

Logging

A new log file is created in logs/run_YYYYMMDD_HHMMSS.log on every app launch via main.py, regardless of success or failure. If no log appears, the app was not launched through main.py.
